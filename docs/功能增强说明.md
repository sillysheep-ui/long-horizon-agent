# 项目功能增强说明文档

## 概述

本次对出行规划 Long-Horizon Agent 项目进行了两类功能增强：

1. **工具生态扩展** — 新增 3 个高德 API 工具（酒店搜索、距离矩阵、美食搜索）
2. **多轮交互能力** — 新增用户追问式交互对话脚本（含长短期记忆机制）

所有新增代码与现有推理、蒸馏、训练流程完全兼容，零破坏性修改。

---

## 一、工具生态扩展

### 1.1 做了什么

新增 3 个工具，均基于项目已有的高德地图 API（`AMAP_MAPS_API_KEY`），无需新增外部依赖：

| 工具 | 文件 | 类名 | 高德 API | 核心输入 |
|------|------|------|----------|---------|
| hotel_search | `tools/tool_hotel.py` | HotelSearch | `v5/place/around` | location + radius + keyword |
| distance_matrix | `tools/tool_distance_matrix.py` | DistanceMatrix | `v3/direction/distance` | origins（`|`分隔多起点） + destination |
| catering_search | `tools/tool_catering.py` | CateringSearch | `v5/place/around` | location + radius + keyword（菜系） |

修改了 3 个现有文件的 6 处注册点：

| 文件 | 注册位置 | 作用 |
|------|---------|------|
| `run_tool_loop_infer.py:35-37` | `TOOL_CLASS_MAP` | 推理时动态加载工具 |
| `data_distill.py:37-39` | `import` 语句 | 蒸馏脚本导入工具类 |
| `data_distill.py:84-86` | `tool_class` 列表 | 蒸馏时 Function Calling 可用工具集 |
| `prompt.py:143-145` | `COLDSTART_SYSTEM_PROMPT` 的 `<tools>` 块 | 冷启动提示词中的工具定义 |
| `prompt.py:328-330` | `llm_judge_system_prompt` 末尾 | 评测 Judge 理解新工具含义 |

### 1.2 有什么意义

**工具从 8 个增至 11 个，本质上扩大了 Agent 的决策空间。**

之前没有 `hotel_search` 和 `catering_search` 时，Agent 只能靠 `poi_search`（通用地点搜索）和 `around_search`（周边搜索）来获取住宿和餐饮信息——这两个工具没有针对性的评分/价格过滤能力。

`distance_matrix` 的加入尤其关键：之前 `route_planning` 只能逐对计算两点间路线，如果要排 6 个景点的最优游览顺序，需要调 15 次 route（C(6,2) = 15），现在一次调用即可。

更重要的是，这些新增工具创造了之前不存在的**决策分叉**：
- 是先找酒店再定路线，还是先定路线再找附近酒店？
- 餐厅是顺路吃还是专门绕路去？
- 多点排序是用 distance_matrix 批量算还是逐个调 route？

模型在这些场景下做出的不同选择，直接决定了工具调用链路的差异——这正是 Agentic RL 需要训练的"编排能力"。

### 1.3 亮点

- **零外部依赖**：三个工具全部使用已有的高德 API key，不需要申请新的第三方服务
- **完全复用现有模式**：代码结构、错误处理、输出格式化（`json2md` + `truncate_text`）与原有 8 个工具完全一致
- **四注册点对齐**：TOOL_CLASS_MAP → data_distill → COLDSTART_SYSTEM_PROMPT → llm_judge，四层注册全部打通，不存在"定义了但某个环节用不了"的遗漏

## 二、多轮交互能力（含长短期记忆）

### 2.1 做了什么

新建 `interactive_chat.py`，实现用户追问式对话交互：

```
┌── 交互循环 ──────────────────────────────────┐
│                                               │
│  用户输入 → tool loop(最多13轮工具调用)        │
│    → 提取<answer>                             │
│    → LLM自动压缩为长期记忆摘要                 │
│    → 等待下一轮用户追问                        │
│                                               │
│  [system] + [长期记忆] + [用户输入]            │
│    → [完整 tool loop] → [answer] → [压缩]     │
│                                               │
└───────────────────────────────────────────────┘
```

**长短期记忆机制**：

- **短期记忆**：当前追问轮次的完整 tool loop（模型输出 + 工具调用 + 工具返回），保留全部细节，不做压缩。本轮结束后释放。
- **长期记忆**：跨追问轮次的结构化摘要，由推理模型每轮自动压缩生成，包含四部分：
  - 用户需求（目标、目的地、时间、预算、偏好）
  - 已给方案要点（行程、推荐项目）
  - 约束变更（用户新增/修改/否定的内容）
  - 待确认事项（仍缺失的信息）

messages 结构随追问轮次演进：

```
第 1 轮: [system] + [用户: "北京天津2日游"] → tool loop → answer → 压缩为摘要S1

第 2 轮: [system] + [记忆: S1] + [用户: "拆成3天"] → tool loop → answer → 压缩为S2

第 3 轮: [system] + [记忆: S1+S2] + [用户: "不去古文化街"] → ...
```

### 2.2 有什么意义

**把 Agent 从"一次性问答"升级为"可迭代协作的应用"。**

批量推理模式下，Agent 输出完就结束了——用户无法纠正、细化、追问。但真实出行规划是一个迭代过程：用户看到方案后自然会想"第二天太赶了"、"这个景点太远换一个吧"、"预算能再压缩吗"。

交互式多轮对话让 Agent 真正像一个"随时可追问的旅行助手"：

- 第一轮给初始方案
- 用户否定/补充 → Agent 基于历史上下文增量调整
- 不需要从头重新规划（已有天气、交通、酒店信息都在历史中）

**长短期记忆解决的核心问题是上下文管理**：

假设 5 轮追问，每轮 tool loop 平均 8 条消息（assistant + tool），加上工具返回的详细文本，消息总数轻松突破 15K tokens。不加记忆管理的话，第 5 轮追问时上下文已经超出模型窗口。

长期记忆压缩把 N 轮历史压缩为几百字的结构化摘要，token 消耗从 O(N) 降为 O(1)。

### 2.3 亮点

**1. 零侵入设计**

`interactive_chat.py` 是一个独立文件，从 `run_tool_loop_infer.py` import 全部核心函数（`parse_tool_calls`、`load_tool`、`has_final_answer` 等 13 个），零代码重复。现有批量推理流程完全不受影响。

**2. 自动记忆压缩**

不是写死规则来截断历史，而是用推理模型本身来理解上下文并生成摘要。压缩 prompt 明确告诉模型：
- 被否定的内容要删除
- 新增约束要补充
- 推翻方案时以新需求为准

这意味着记忆是有"理解力"的——模型是真的在"管理信息"而不是简单地"截取前 N 字"。

**3. 完整的防护机制**

每轮追问的 tool loop 仍然保留全部防护逻辑：
- `tool_first` 强制执行（必须先调工具再出 answer）
- 重复调用检测（同一工具同一参数同一结果触发告警）
- 连续无效工具轮次限制
- 强制收束（达到最大轮次后强制输出 answer）

**4. 内置命令支持**

```
exit/退出     — 结束对话
reset/重置    — 清空历史，重新开始（保留 system prompt）
history/历史  — 查看当前长期记忆摘要
help/帮助     — 显示命令说明
```

## 四、使用方式

### 交互式对话

```bash
# transformers 后端
python interactive_chat.py \
  --model_dir saved/output/qwen3_4b_sft_merged_420/ \
  --tools_dir tools/

# vllm 后端（更快）
python interactive_chat.py \
  --infer_backend vllm \
  --model_dir saved/output/qwen3_4b_sft_merged_420/ \
  --tools_dir tools/
```

### 批量推理（不变）

```bash
bash infer.sh   # 仍使用 run_tool_loop_infer.py，TOOL_CLASS_MAP 自动包含新工具
```
